# 小红书账号诊断器 (XHS Account Doctor)

把小红书创作者后台导出的「笔记列表明细表.xlsx」变成一份能直接照着做的诊断看板——不是摆数字，是找病根。

## 何时使用

- 用户说"账号诊断 / 跑洞察 / 跑复盘 / 看板" → 跑诊断看板
- 用户说"对标分析 / 自己 vs 对标 / 账号对比" → `--compare` 并排对比
- 用户有多个账号/平台导出 → `--by-source` 横向对比

## 环境依赖

Python 3.8+，依赖 pandas + openpyxl：

```bash
pip install pandas openpyxl
```

## 工作流

### ① 账号诊断看板

```bash
python scripts/account_doctor.py
```

- 默认自动扫描 `~/Downloads` 下文件名含"笔记"的 xlsx（多份自动合并）。
- 也可显式传入：`python scripts/account_doctor.py "路径1.xlsx" "路径2.xlsx"`
- 输出：`outputs/账号诊断看板_YYYYMMDD_HHMM.html`

看板含 6 章：①单篇红黑榜 ②爆款规律 ③内容线对比 ④流量健康诊断 ⑤诊断结论（四段漏斗+病根归因）⑥P0/P1/P2 可执行优化清单。

### ② 自己 vs 对标 对比看板

```bash
python scripts/account_doctor.py --compare "自己数据.xlsx" "对标画像.xlsx"
```

- 对标侧用公开可比指标（粉丝/赞藏评/内容线占比），**不编数**。
- 对标账号必须先确认还在更新（停更号不进池）。

### ③ 自定义内容线打标

每条内容按标题关键词自动打"内容线"标签。默认规则是示例（干货/热点），**使用前应让用户改成自己账号的内容线**：

```bash
python scripts/account_doctor.py --config config.json
```

`config.json` 参照 `scripts/config.example.json`：

```json
{
  "default_tag": "日常",
  "tag_rules": {
    "你的内容线A": ["关键词1", "关键词2"],
    "你的内容线B": ["关键词3"]
  },
  "score_weights": {"fans": 5, "interactions": 1, "exposure": 0.01}
}
```

## 数据口径铁律（实战踩坑得出，详见 references/methodology.md）

1. **必须合并"全部"导出表，不能只挑最新的几份**——每一份只是某个时间点的切片，漏掉早期导出会把结论倍数算偏。
2. **去重口径**：计数类字段（曝光/观看/赞/评/藏/涨粉）取 `max`（只增不减）；**封面点击率取最新快照**（它是比率、会回落，取 max 会留下旧快照的虚高值）；派生指标（互动数/互动率/涨粉效率/得分）用合并后的计数**重算**。
3. **封面点击率是小数**（0.112 = 11.2%），导出表第 5 列本来就是小数，别当百分数再除一次。
4. 曝光可以为 0（导出时该篇还没跑量），不是脏数据。

## 诊断逻辑（脚本自动执行，AI 负责解读与追问）

- 四段漏斗：曝光→观看→互动→涨粉，定位最大漏点（末端转化 <5% 判为断裂）。
- 黑榜分桶：没流量（发布/推荐问题）vs 有流量没接住（缺关注引导）vs 有效涨粉。
- 埋没检测：曝光<100 但互动率进前 40% 的笔记 = 高质量被埋没。
- 策略分工：曝光最高的线 = 流量引擎；互动率最高的线 = 质量引擎；两者互相导流。

AI 拿到看板输出后应做的三件事：①用一句话说清最大漏点在哪 ②把 P0 建议翻译成用户能当天执行的动作 ③问用户要缺失的上下文（发帖时间规律/是否有关注引导），不凭猜测下结论。

## 红线

- 所有结论必须能追溯到后台真实数字，不编造、不脑补。
- 不承诺涨粉或任何效果；预期数字只做保守估算并明确标注"估算，非承诺"。
- 数据来自用户自己的官方导出，产物留在本地，不外传。
- 本工具做诊断分析，不涉及任何爬虫、买卖数据、刷量服务。
